# Rule 12 — Deterministic hook context and skill-loading enforcement

Relevant project skills are selected and enforced by hook state, not by model judgment. Claude Code documents hooks as lifecycle commands that receive JSON on stdin and can add model-facing context with `hookSpecificOutput.additionalContext`; use that field for steering and reserve `systemMessage` for user-facing UI warnings (https://code.claude.com/docs/en/hooks). Claude Code skills expose `description` and `when_to_use` to help the model decide when to invoke a skill, but deterministic load-before-write behavior belongs in `PreToolUse` enforcement, not in skill prose (https://code.claude.com/docs/en/skills).

## Runtime map

- `SessionStart` injects standing context and handles context lifetime deliberately. `startup` and `clear` reset state, while `resume` and `compact` invalidate context-loaded skill evidence without carrying it into the next prompt. Claude and Codex both document `startup`, `resume`, `clear`, and `compact` as session-start matcher values; `compact` is the post-compaction re-injection point (https://code.claude.com/docs/en/hooks, https://developers.openai.com/codex/hooks).
- `UserPromptSubmit` scores prompt text with explicit `$skill` and `/skill` tokens, non-generic skill names, and curated `metadata.keywords`. It does not score `description`, `when_to_use`, command prose, or legacy pattern metadata. Repo-managed skill frontmatter must not add `intent-patterns:`; use literal `metadata.keywords` and `metadata.file-triggers` instead. Matches are recorded as pending and injected as model-facing context so the agent has the next tool opportunity to load the skill.
- `PreToolUse` allows the agent's next tool call to acquire required context while a skill is pending: observable skill-loading calls and Code Atlas query calls are allowed. It hard-blocks governed command, content, delegation, and research tools only when the attempted tool call is neither an observable skill load nor a Code Atlas query. Tool-scope matching uses structured file paths from payloads and patch headers against `metadata.file-triggers`; it does not scan command text for prompt keywords. Codex shell command tools are governed, but only reader commands that target `SKILL.md` count as observable loads. The denial uses `hookSpecificOutput.permissionDecision = "deny"` on tool events, matching the Claude and Codex hook contracts (https://code.claude.com/docs/en/hooks, https://developers.openai.com/codex/hooks). Advisory context is emitted only for newly pending file-triggered skills and at most one Code Atlas `pre-edit` hint per target per turn; already loaded skills and repeated no-op matches stay silent.
- `PostToolUse` records observable skill loads and structured evidence breadcrumbs, including successful `code_atlas_query`, `npm run code-atlas:query`, and `node scripts/code-atlas/query.mjs` calls. A skill clears only when the `Skill` tool loads it or an actual `SKILL.md` file read is observed through `Read`, MCP, or a shell reader command exposed by Codex; slash commands, `$skill` tokens, inline mentions, and Code Atlas queries are request/evidence signals, not skill loads.
- `SubagentStart` injects pending skill context because non-fork subagents start with fresh isolated context and do not inherit loaded skills or files already read by the parent (https://code.claude.com/docs/en/sub-agents). Use subagent frontmatter `skills:` when a subagent must preload full `SKILL.md` content (https://code.claude.com/docs/en/sub-agents).
- In the shared context hook layer, `Stop` and `SubagentStop` run response-shape detectors and re-inject corrections with `hookSpecificOutput.additionalContext` in Claude. Codex Stop/SubagentStop require JSON stdout and use `decision: "block"` to continue with a correction prompt when a repo-local Codex context registration wires those scripts (https://developers.openai.com/codex/hooks).
- `TaskCompleted` and `PermissionDenied` are Claude-only enforcement points in this repo. Codex does not currently document those events in its hook matcher table, so `.codex/hooks.json` intentionally omits them (https://developers.openai.com/codex/hooks).
- `SessionEnd` clears session state. Claude documents SessionEnd as cleanup-only with no decision control (https://code.claude.com/docs/en/hooks).

## State and ownership

- State lives under `.tmp/agent-hooks` by default and is keyed by a path-safe validated session id. Enforcement facts that can become stale across prompts — pending skills, response corrections, evidence breadcrumbs, one-shot Code Atlas advisories, and the last prompt — are scoped to the active turn (`turn_id` in Codex, prompt sequence in Claude). Context-loaded skill evidence is scoped to a context epoch and is invalidated on resume/compact.
- Canonical hook source lives in `.claude/hooks/**` and shared logic lives in `scripts/agent-hooks/**`. `npm run sync:llm` mirrors `.claude/hooks/**` into `.codex/hooks/**`; edit the Claude owner and sync instead of hand-editing generated mirrors.
- `scripts/skills/sync-llm.mjs` is the only writer for generated agent-surface mirrors. Preserve its atomic write path: generated files are written through unpredictable temp names, exclusive creation, and rename, with symlink/race regression coverage in `tests/agent-surfaces.test.ts`.
- `.claude/settings.json` is the maintainer Claude context-hook registration owner. `.codex/hooks.json` is the native Codex consumer hook registration owner and must stay limited to the shipped supaschema consumer hooks. Shared Codex context hook scripts remain generated mirrors of Claude hook sources, but they are not registered in the published `.codex/hooks.json`.
- `scripts/guards/check-hook-import-graph.mjs` proves hook runtime modules import only `node:` builtins and relative files, so hooks run without package installation.

## Response-shape policy

Stop-time detectors enqueue and auto-resolve session-scoped corrections for hedge density, completion claims with open items, verification claims without evidence breadcrumbs, decision menus after direct directives, deferral language, and tool failure without retry. `PreToolUse` also blocks further edits while evidence-related corrections remain unresolved.

STOP if a governed surface is edited while a matched required skill is pending, if hook output uses `systemMessage` where model-facing context is required, if a hook failure silently allows a governed action, if a hook imports non-builtin non-relative runtime code, if generated mirrors drift from their `.claude/**` owner, or if `sync-llm` reintroduces predictable temp paths, check-then-write mirror writes, or symlink-following temp-file behavior.

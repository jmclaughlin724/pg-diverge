# Rule 12 — Deterministic hook context and skill-loading enforcement

## Contract

This rule owns deterministic hook context and skill-loading enforcement: hook state selects relevant skills, skill loads are observable-only, governed work is blocked until required context is loaded, and the repository boundary runs before every other `PreToolUse` concern.

Relevant project skills are selected and enforced by hook state, not by model judgment. Claude Code documents hooks as lifecycle commands that receive JSON on stdin and can add model-facing context with `hookSpecificOutput.additionalContext`; use that field for steering and reserve `systemMessage` for user-facing UI warnings (https://code.claude.com/docs/en/hooks). Claude Code skills expose `description` and `when_to_use` to help the model decide when to invoke a skill, but deterministic load-before-write behavior belongs in `PreToolUse` enforcement, not in skill prose (https://code.claude.com/docs/en/skills).

## Runtime map

- `SessionStart` injects standing context and handles context lifetime deliberately. `startup`, `clear`, and Claude's `fork` source reset state, while `resume` and `compact` invalidate context-loaded skill evidence without carrying it into the next prompt. Codex documents `startup`, `resume`, `clear`, and `compact`; Claude documents those values plus `fork`. Claude also permits the `auto` permission mode while Codex does not, and Claude's `model` field is optional at this event. Validate required fields and enums per runtime, preserve unknown future fields, and treat `compact` as the post-compaction re-injection point (https://code.claude.com/docs/en/hooks, https://learn.chatgpt.com/docs/hooks).
- `UserPromptSubmit` scores prompt text with explicit `$skill` and `/skill` tokens, non-generic skill names, and curated `metadata.keywords`. It does not score `description`, `when_to_use`, command prose, or legacy pattern metadata. Claude records matches as pending until an observable load clears them. Codex receives the same matched-skill context as advisory because its documented hook interception cannot observe every desktop wrapper path. Repo-managed skill frontmatter must not add `intent-patterns:`; use literal `metadata.keywords` and `metadata.file-triggers` instead.
- `PreToolUse` first enforces the canonical repository boundary for every supported local tool. It denies a working directory, structured path, patch target, shell operand, redirection, or resolved symlink target outside the canonical project root; denies every worktree command and every linked-worktree checkout; and denies branch creation or switching unless the current user prompt explicitly authorizes that branch mutation. This boundary is fail-closed and runs before skill, evidence, or Bash-safety dispatch. After that boundary passes, `PreToolUse` allows the agent's next tool call to acquire required context while a skill is pending: observable skill-loading calls and Code Atlas query calls are allowed. It hard-blocks governed command, content, delegation, and research tools only when the attempted tool call is neither an observable skill load nor a Code Atlas query. Tool-scope matching uses structured file paths from payloads and patch headers against `metadata.file-triggers`; it does not scan command text for prompt keywords. Codex shell command tools are governed, but only structured reader command segments that target `SKILL.md` count as observable loads; non-reader command segments that merely print, echo, or mention `SKILL.md` MUST NOT clear pending skills. Reader detection MUST use the shared shell command parser and MUST recognize nested `bash -lc` / `sh -c` / `zsh -c` reader commands, multiple `SKILL.md` paths in one command, POSIX separators, Windows separators, and simple skill-name brace alternates. The denial uses `hookSpecificOutput.permissionDecision = "deny"` on tool events, matching the Claude and Codex hook contracts (https://code.claude.com/docs/en/hooks, https://learn.chatgpt.com/docs/hooks). Denial feedback MUST tell the agent the exact observable skill-load command to run and MUST avoid passive "may load" phrasing. Advisory context is emitted only for newly pending file-triggered skills and at most one Code Atlas `pre-edit` hint per target per turn; already loaded skills and repeated no-op matches stay silent.
- Inside a subagent the `PreToolUse` skill gate is advisory, not blocking. The repository, worktree, and active-branch boundary remains hard-blocking. Claude Code fires `PreToolUse` for tool calls made inside a subagent and marks them with an `agent_id` field present only for in-subagent calls (https://code.claude.com/docs/en/hooks), but `SubagentStart` cannot block and a subagent may run under a restricted `tools:` set without `Skill`/`Read`, so a hard skill-load deny would deadlock it with no way to clear the gate. When `agent_id` is present the skill gate emits the pending-skill names as `additionalContext` instead of denying; hard skill-load enforcement stays in the main session and the orchestrator applies subagent findings. The response-evidence gate downgrades the same way, because a subagent cannot revise the parent's final response.
- `PostToolUse` records observable skill loads and structured evidence breadcrumbs, including successful `code_atlas_query`, `npm run code-atlas:query`, and `node scripts/code-atlas/query.mjs` calls. Claude dispatches failures through the separate `PostToolUseFailure` event, which MUST record a failed command even when no synthetic `tool_response` exists and MUST run surface sync for a partially committed canonical mutation. Codex has no separate failure event: supported nonzero Bash executions still reach `PostToolUse`, so shared outcome parsing remains required there. Codex presents both direct and code-mode nested unified exec calls to hooks under the canonical `Bash` name; native Codex matchers MUST use `Bash`. Raw `exec_command` and `functions.exec_command` names may be normalized defensively inside shared payload and transcript adapters, but they MUST NOT be registered as native matcher names. Command evidence MUST be limited to recognized verification domains such as guard, test, typecheck, lint, package, build, sync, GitHub checks, and Code Atlas. Source and inventory reads such as `sed`, `cat`, file reads, and ad hoc inspection commands MUST NOT become verification evidence or failed verification blockers based on stdout, stderr, or transcript text. A failed shell event whose structured Claude `error` or Codex `tool_response` contains a shell `command not found` diagnostic MUST record a separate `tool-incident` breadcrumb; that breadcrumb is disclosure evidence, not verification evidence, and a later successful retry MUST NOT erase it. Command outcome parsing MUST trust structured status and exit fields or execution-status lines such as `Process exited with code 0`; it MUST NOT scan arbitrary source output such as `process.exitCode = 2` for exit codes. A skill clears only when the `Skill` tool loads it or an actual `SKILL.md` file read is observed through `Read`, MCP, or a shell reader command exposed by Codex; shell-read detection MUST normalize POSIX and Windows path separators before matching `*/skills/*/SKILL.md`. Slash commands, `$skill` tokens, inline mentions, and Code Atlas queries are request/evidence signals, not skill loads.
- Code Atlas evidence comes only from the local CLI or `mcp__supaschema__code_atlas_query`. Claude's PostToolUse matcher dispatches that local MCP tool to the classifier; removed direct Code Atlas tool names record nothing and cannot satisfy local Atlas completion claims.
- `SubagentStart` injects pending skill context because non-fork subagents start with fresh isolated context and do not inherit loaded skills or files already read by the parent (https://code.claude.com/docs/en/sub-agents). Use subagent frontmatter `skills:` when a subagent must preload full `SKILL.md` content (https://code.claude.com/docs/en/sub-agents).
- `Stop` and `SubagentStop` run the response-shape and evidence detectors for both Claude and Codex. When a shell command-not-found incident is recorded, the final response MUST begin with `Tool incident:`, explicitly name `command not found`, and give impact and recovery evidence before the outcome even when a retry succeeded. Response-shape detectors MUST use unambiguous disposition evidence: a bare `if you want` without an offer of deferred agent work is not a deferral, and `could` is not a hedge because it also expresses capability and historical or counterfactual risk. When a correction is required, the hook returns the runtime-specific continuation decision and marks that correction as blocked once so `stop_hook_active` cannot create an infinite continuation loop. Codex documents both events as turn-scoped lifecycle hooks and defines `decision: "block"` as continuing the turn or subagent (https://learn.chatgpt.com/docs/hooks).
- `TaskCompleted` is a Claude-only enforcement point in this repo. `PermissionDenied` is intentionally unregistered: Claude fires it only after an auto-mode classifier denial, ignores exit-code/stderr blocking there, and exposes only `hookSpecificOutput.retry = true` as a useful model control; this repo does not retry denied actions. Codex documents neither event, so `.codex/hooks.json` omits both (https://code.claude.com/docs/en/hooks, https://learn.chatgpt.com/docs/hooks).
- `SessionEnd` clears session state in both runtimes and is advisory only. Claude reports lifecycle-specific reasons; current Codex support reports `other`, caps the command timeout at three seconds, and cannot be steered by hook output (https://code.claude.com/docs/en/hooks, https://learn.chatgpt.com/docs/hooks).

## State and ownership

- State lives under `.tmp/agent-hooks` by default, may be redirected with `STATE_DIR` for isolated hook runs and tests, and is keyed by a path-safe validated session id. Pending skills, evidence breadcrumbs, one-shot Code Atlas advisories, and the last prompt are scoped to the active turn (`turn_id` in Codex, prompt sequence in Claude). Context-loaded skill evidence is scoped to a context epoch, invalidated on resume/compact, and reset for startup/clear/fork. Hook handlers MUST serialize session-state mutation through `scripts/agent-hooks/state.mjs` so parallel tool-result events cannot overwrite observed skill loads or evidence from the same session.
- Response corrections live in a bounded session ledger keyed by `main` or a validated `agent_id`, not by turn. Emitted signatures remain actor-scoped so identical corrections are one-shot across turn IDs; preserve the main lane only for an exact hook-generated continuation prompt, clear it for a new user prompt, and clear only the matching agent lane on `SubagentStart`.
- Canonical hook source lives in `.claude/hooks/**` and shared logic lives in `scripts/agent-hooks/**`. `npm run sync:llm` mirrors `.claude/hooks/**` into `.codex/hooks/**`; edit the Claude owner and sync instead of hand-editing generated mirrors.
- Skill authoring standards and templates must route deterministic skill loading through this hook path. New SKILL.md metadata fields are inert until `scripts/agent-hooks/skills.mjs` reads them and `scripts/guards/agent-surface/check-agent-hooks.mjs` validates them; do not document a custom field as active enforcement before both owners exist.
- `scripts/skills/sync-llm.mjs` is the only writer for generated agent-surface mirrors and generated source-repo Codex hook registration. Preserve its atomic write path: generated files are written through unpredictable temp names, exclusive creation, and rename, with symlink/race regression coverage in `tests/agent-hooks/agent-surfaces.test.ts`.
- Runtime skill discovery MUST use `.claude/skills/**` for Claude and generated `.agents/skills/**` for Codex. `.codex/skills/**` is not a source-repo skill root.
- Rule 22 owns source-repo hook topology, generated Codex hook registration, generated skill mirrors, and the public/private branch boundary. This rule owns event behavior: skill selection, observable-load enforcement, evidence capture, and subagent downgrades.
- `scripts/guards/agent-surface/check-hook-import-graph.mjs` proves hook runtime modules import only `node:` builtins and relative files, so hooks run without package installation.

## Completion policy

Final answers follow the root `AGENTS.md` contract and use recorded source or command evidence for verification claims. `Stop` and `SubagentStop` enforce the restored response-shape contract, including leading disclosure for recorded shell command-not-found incidents, unsupported completion claims, unresolved recorded verification failures, deferral after direct instructions, and missing architecture or verification disposition. Claude also blocks positive verification claims without successful evidence because its configured producer path is observable. Codex MUST NOT block solely because positive evidence is absent: specialized tool paths may opt out of the default hook path, so missing `PostToolUse` evidence is unknown rather than a recorded failure. Codex still blocks claims contradicted by recorded failures, while unsupported paths remain instruction-governed. `TaskCompleted` also blocks unresolved pending skills or response corrections. Claude hard-blocks governed tool calls while matched skills are pending; Codex receives advisory load context. The repository, worktree, and active-branch boundary blocks supported local tools in both runtimes and does not downgrade inside subagents. Hooks are guardrails, not an operating-system sandbox.

STOP if the repository boundary permits a supported local tool to target outside the canonical project root, permits any worktree command or linked-worktree checkout, permits an unauthorized branch creation or switch, or downgrades for a subagent; if a governed surface is edited while a matched required skill is pending; if the skill or response-evidence gate hard-denies a subagent tool call (`agent_id` present) instead of downgrading to advisory; if hook output uses `systemMessage` where model-facing context is required; if a hook failure silently allows a governed action; if Claude failure events bypass evidence or partial-mutation sync; if a recorded shell command-not-found incident is buried after the outcome or euphemized as only a malformed or read-only search; if generated mirrors drift from their `.claude/**` owner; if a tracked hook registration or guard depends on a gitignored source-repo runtime file; if GitHub checks are claimed green without successful `github-checks` evidence or while failed `statusCheckRollup` evidence remains unresolved; if a source or inventory read is recorded as verification evidence or a failed verification blocker; if source-repo Claude or Codex shell commands match more than one `PreToolUse` Bash safety hook command; if Codex repo-local commands depend on an undocumented project-root environment variable instead of resolving the git root; if hook event handlers bypass serialized session-state mutation; or if `sync-llm` reintroduces predictable temp paths, check-then-write mirror writes, or symlink-following temp-file behavior.

## Verification

When hook state, skill matcher, context injection, generated mirrors, or runtime adapters change, run:

```bash
npm run sync:llm
npm run guard:agent
npm run guard
```

Run focused hook/skill-matcher tests for the changed module. For GitHub check evidence behavior, run:

```bash
npm test -- tests/agent-hooks/agent-hook-core.test.ts
```

For session-state concurrency behavior, `tests/agent-hooks/agent-hook-core.test.ts` MUST cover parallel Codex `PostToolUse` skill loads for the same session. For Codex shell-read skill loads, `tests/agent-hooks/agent-hook-core.test.ts` MUST cover POSIX separators, Windows path separators, one nested shell reader command that loads multiple pending skills, non-reader `SKILL.md` command tokens that must not clear pending skills, and preservation of every explicit skill token beyond keyword-match caps.

## Failure behavior

Fix the canonical `.claude/**` hook, `.claude/settings.json` registration, or shared `scripts/agent-hooks/**` owner, then sync generated mirrors and `.codex/hooks.json`. Do not patch generated mirrors directly, use user-facing `systemMessage` for model steering, or fail open on governed writes.

## Done means

Supported local tools cannot cross the canonical project root, use a linked worktree, invoke a worktree command, or create or switch branches without explicit current-prompt authorization. Required skills are detected, Claude loads are enforced before governed work, Codex receives advisory load context, runtime-specific SessionStart values are accepted, Claude failures and shell command-not-found incidents are recorded, both runtimes clear state at SessionEnd, `Stop` and `SubagentStop` response corrections run with loop protection and incident-leading disclosure, mirrors are synced, and the hook graph imports are safe.

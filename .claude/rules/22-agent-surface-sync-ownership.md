# Rule 22 - Generated agent-surface sync ownership

## Contract

`scripts/skills/sync-llm.mjs` is the single idempotent writer for generated Claude-to-Codex, Claude-to-Agents, public-skill, and consumer-bundle outputs. Generated surfaces are never independent inputs.

Synchronization is a write operation. There is no check-only sync command or read-only parity mode. Run the writer whenever a canonical surface may have changed; it skips content-identical writes and removes stale managed output while preserving Git-ignored local overlays.

## Ownership

- `.claude/settings.json` owns maintainer Claude hook registration.
- `.claude/hooks/**`, `.claude/rules/**`, `.claude/skills/**`, and `.claude/agents/**` own their generated Codex and Agents projections.
- Public skills are discovered from parsed skill frontmatter with `metadata.public: true`; no separate skill-name list owns publication.
- `.codex/config.toml` remains a direct runtime owner and is not generated by this writer.
- Consumer templates are rendered from the same product-hook definitions but contain only generated-migration protection and schema-write workflow hooks.

## Hook registration projection

- Source Claude and generated Codex register silent `SessionStart` and `SessionEnd` lifecycle hooks.
- `UserPromptSubmit` performs prompt-scoped skill matching without storing prompt text.
- Claude context `PreToolUse` uses `Bash|Edit|MultiEdit|NotebookEdit|Read|Write|apply_patch`; generated Codex context `PreToolUse` uses `Bash|apply_patch`. These are the tools with an applicable Bash policy or a structured file target in the corresponding runtime.
- Context `PostToolUse` is limited to `Bash|Read|Skill`. Claude `PostToolUseFailure` is limited to `Bash`; Codex records supported nonzero Bash results through `PostToolUse`.
- Claude product and surface-sync edit hooks match `Write|Edit|MultiEdit|apply_patch`; Codex product and surface-sync hooks match `apply_patch`.
- `Stop` and `SubagentStop` run only the structured verification-conflict check. No task-completion or worktree lifecycle enforcement hook is registered.
- Surface sync is not registered for Bash, failure, Stop, or unrelated events.
- Codex commands resolve the repository with `git rev-parse --show-toplevel` and provide a Windows equivalent; they do not rely on undocumented project-root environment injection.

## Synchronization behavior

- The surface-change `PostToolUse` hook inspects the structured edit target before doing other work.
- Only explicit edits to `.claude/agents/**`, `.claude/hooks/**`, `.claude/rules/**`, `.claude/skills/**`, `.claude/settings.json`, or `scripts/skills/sync-llm.mjs` invoke the writer.
- Unrelated edits return immediately and do not hash files, create digest state, or repair generated drift.
- Writer failures are visible and non-blocking at the hook boundary. The explicit writer command and guards remain blocking validation commands when their process exits unsuccessfully.
- Successful writes are atomic and content-aware. Running `npm run sync:llm` repeatedly is the supported validation path.

## Enforcement chain

- Hook topology: `scripts/guards/agent-surface/check-agent-hooks.mjs`.
- Import closure: `scripts/guards/agent-surface/check-hook-import-graph.mjs`.
- Synchronizing guard step: `npm run guard:agent` invokes `npm run sync:llm` directly before its read-only topology guards.
- Executable behavior: focused tests under `tests/agent-hooks/**` cover registration, target-first synchronization, writer repair, generated consumers, and hook runtime behavior.
- `npm run guard:agent` runs these steps in order.

## Verification

```bash
npm run sync:llm
npm run guard:agent
npm test -- tests/agent-hooks/sync-llm.test.ts tests/agent-hooks/agent-hook-core.test.ts tests/agent-hooks/agent-surfaces.test.ts tests/agent-hooks/agent-hooks.test.ts
```

For consumer-boundary changes, also run `npm run guard:public-surface`, `npm run check:package`, and `npm pack --dry-run --json`.

## Done means

- The actual sync writer has run after the final canonical edit.
- Generated Codex, Agents, public-skill, and consumer surfaces reflect their parsed canonical inputs.
- Maintainer registrations implement the narrow event contract above.
- Consumer templates contain exactly the two Supaschema product hooks with runtime-correct edit matchers.
- No check-only sync command, digest state, generated-target trigger, or duplicate publication list remains.

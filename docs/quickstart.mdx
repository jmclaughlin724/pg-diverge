---
title: "Quickstart"
description: "Install supaschema, write a declarative schema file, generate a replay-safe PostgreSQL migration from configured sources, and validate it."
keywords: ["quickstart", "first migration", "diff", "check", "types"]
---

Use this page to generate and check one migration.

The examples use the neutral paths `database/schemas` and `database/migrations`. If install selected provider-specific paths, use the values in `supaschema.config.json`.

<Steps>
  <Step title="Install">
    Install supaschema in the project that owns your schema files:

    ```bash
    npm install supaschema
    npx supaschema --version
    ```

  </Step>

  <Step title="Write schema">
    Create one schema file:

    ```bash
    mkdir -p database/schemas
    ```

    ```sql database/schemas/app.sql
    CREATE SCHEMA app;

    CREATE TABLE app.accounts (
      id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
      name text NOT NULL
    );

    ALTER TABLE app.accounts ENABLE ROW LEVEL SECURITY;

    CREATE POLICY accounts_select ON app.accounts
      FOR SELECT
      TO public
      USING (true);
    ```

    Your schema files are the source of truth. supaschema writes the migration.

  </Step>

  <Step title="Generate">
    Generate the migration:

    ```bash
    npx supaschema diff
    ```

    You will see output like this:

    ```text
    Parsed schema tree (3 objects)
    Computed diff (4 operations)
    Created: database/migrations/20240101120000_migration.sql
    ```

    Review the generated file. It should include a lineage marker and guarded SQL:

    ```sql database/migrations/20240101120000_migration.sql
    -- Generated by supaschema x.y.z.
    -- supaschema: lineage from=0000000000000000... to=4db806bc9b786ea2...

    CREATE SCHEMA IF NOT EXISTS app;
    CREATE TABLE IF NOT EXISTS app.accounts (...);
    ```

  </Step>

  <Step title="Check">
    Check the migration before applying it:

    ```bash
    npx supaschema check database/migrations/20240101120000_migration.sql
    ```

    A passing check reports that the migration is replay-safe.

    <Warning>
      If `check` reports issues, review the flagged statements before applying
      the migration. supaschema fails closed when it cannot prove safety.
    </Warning>

  </Step>

  <Step title="Apply">
    supaschema generates migrations. Your normal PostgreSQL runner applies them.

    ```bash
    psql "$DATABASE_URL" -f database/migrations/20240101120000_migration.sql
    ```

    Supabase projects can apply generated files with the Supabase CLI:

    ```bash
    supabase db push
    ```

    <Note>
      supaschema never applies migrations to your target database.
    </Note>

  </Step>

  <Step title="Generate types">
    `diff` refreshes configured TypeScript and Zod outputs by default. Run `types` directly when you need an explicit refresh:

    ```bash
    npx supaschema types
    ```

  </Step>
</Steps>

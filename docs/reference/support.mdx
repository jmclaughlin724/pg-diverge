supaschema is dual-licensed under AGPL-3.0-only and a commercial license.

Use the AGPL lane for compliant open-source, internal, and CI use. Use the
commercial lane when you need rights or support terms that are not granted by
the AGPL.

## When to ask

Open a commercial/support request when you need to:

- embed supaschema in a proprietary product, CLI, SDK, or hosted service;
- distribute supaschema without releasing the corresponding source required by
  the AGPL;
- offer supaschema-powered functionality to third parties as part of a SaaS or
  managed platform;
- define support, response-time, procurement, security-review, or compliance
  terms in a signed agreement.

You usually do not need a commercial license to run supaschema as a development
dependency or CI command against your own repositories when you comply with the
AGPL.

## Channels

- Public bugs and feature requests belong in
  [GitHub issues](https://github.com/jmclaughlin724/supaschema/issues).
- Commercial and support intake belongs in the
  [commercial support template](https://github.com/jmclaughlin724/supaschema/issues/new?template=commercial_support.md).
- Security vulnerabilities belong in the
  [private advisory flow](https://github.com/jmclaughlin724/supaschema/security/advisories/new).

Do not include secrets, database URLs, customer data, private schema dumps, or
confidential commercial terms in public issues.

## Boundaries

This repository ships the CLI, library, GitHub Action, docs, and local package
setup flow. It does not include hosted CI, billing, marketplace distribution,
license enforcement, paid cloud services, or SLA terms.

Commercial rights and support levels exist only in a signed agreement. The
public issue template is an intake path, not a grant of rights or a support
contract.

See [Commercial License](https://github.com/jmclaughlin724/supaschema/blob/main/LICENSE-COMMERCIAL.md)
and the [support matrix](/reference/support-matrix) before sending proprietary
or provider-specific details.

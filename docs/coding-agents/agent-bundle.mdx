The agent bundle gives coding agents the same migration workflow that humans use: edit declarative SQL, generate with `diff`, check replay safety, and never hand-edit generated migration files.

## Installed surfaces

The downloadable consumer agent bundle is intentionally narrow.

| Surface | Files |
| --- | --- |
| Shared install prompt | `.agents/prompts/supaschema-install.md` |
| Shared skill | `.agents/skills/supaschema` |
| Claude skill and rule | `.claude/skills/supaschema`, `.claude/rules/supaschema.md` |
| Claude hooks | `.claude/hooks/auto-diff-on-schema-change.mjs`, `.claude/hooks/block-generated-migration-edits.mjs`, `.claude/hooks/sync-llm-on-claude-surface-change.mjs` |
| Codex mirrors | `.codex/skills/supaschema`, `.codex/rules/supaschema.rules` |
| Codex hooks | `.codex/hooks.json`, `.codex/hooks/auto-diff-on-schema-change.mjs`, `.codex/hooks/block-generated-migration-edits.mjs`, `.codex/hooks/sync-llm-on-claude-surface-change.mjs` |

`postinstall` and `supaschema init` also write or merge hook registration files into the consuming project:

| Runtime | Generated registration  |
| ------- | ----------------------- |
| Claude  | `.claude/settings.json` |
| Codex   | `.codex/hooks.json`     |

`.claude/settings.json` is generated by `bin/scaffold.mjs`. `.codex/hooks.json` is the packaged consumer registration source and is merged into the consuming project by the same scaffolder.

The managed `AGENTS.md` and `CLAUDE.md` addenda point agents to `.agents/prompts/supaschema-install.md` before setup or schema work. That prompt tells agents not to clone the supaschema source repository for normal use, lists the installed files, defines their post-install checks, and tells them how to report a clean install.

## npx skills lane

The public `npx skills` source is intentionally narrower than the npm setup
surface:

```bash
npx skills add https://github.com/jmclaughlin724/supaschema/tree/main/skills/supaschema
```

Do not use the repository root as the Skills source. The Skills CLI scans
standard agent skill directories, and this repository contains maintainer skill
mirrors for developing supaschema itself.

That source mirrors `.claude/skills/supaschema/SKILL.md` into
`skills/supaschema/SKILL.md`. It installs Agent Skill context only. It does not
install passive rule files, hook scripts, hook registration, config, or schema
directories.

Rules and hooks are included by `npm install supaschema` through the
`postinstall` scaffold. If lifecycle scripts did not run, `npx supaschema init`
uses the same scaffold and writes the same rule, skill, hook, config, and
manifest surfaces.

## Hook behavior

The installed hooks enforce only supaschema migration policy:

| Hook | Event | Purpose |
| --- | --- | --- |
| `block-generated-migration-edits.mjs` | `PreToolUse` | Blocks edits to generated migration SQL when the lineage marker is present. |
| `auto-diff-on-schema-change.mjs` | `PostToolUse` | Watches schema-tree SQL writes, runs `supaschema diff`, then runs `supaschema check`. |
| `sync-llm-on-claude-surface-change.mjs` | Claude `PostToolBatch`, Codex `Stop` | Keeps installed `.agents` and Codex mirrors aligned when the consumer edits the shipped `.claude` supaschema rule or skill. |

`auto-diff-on-schema-change.mjs` is the hook that triggers the default migration workflow after configured schema files are edited. It writes the migration when `workflow.schema_diff` is `"on_schema_write"` and runs the replay-safety check when `workflow.migration_check` is `"after_schema_diff"`.

The hooks generate and prove migrations. They never apply migrations to a database.

## Repo-local tooling

Maintainer Claude/Codex optimization infrastructure is not part of the download or install scaffold by default.

Keep these repo-local unless the consumer contract explicitly changes:

- `.claude/hooks/context-*`
- `.codex/hooks/context-*`
- `scripts/agent-hooks/**`
- optimizer skills
- internal rules
- `.claude/agents/**`
- `.codex/agents/**`
- `.codex/config.toml`

If one of these surfaces becomes part of the consumer contract, update the package allowlist, scaffold, package tests, and [Package Boundary](/reference/package-boundary) in the same change.

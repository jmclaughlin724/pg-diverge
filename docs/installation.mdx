Install supaschema as a dev dependency in the project that owns your schema files.

The install step also prepares config, schema folders, migration folders, and agent guidance when they are missing.

## Requirements

| Requirement | Minimum |
| --- | --- |
| Node.js | 22.12.0 |
| PostgreSQL target | 15 |

supaschema works with PostgreSQL 15+ directly and with managed PostgreSQL providers.

Supported targets include Supabase, Neon, AWS RDS/Aurora PostgreSQL, Google Cloud SQL, AlloyDB, Azure Database for PostgreSQL, Render, Railway, Heroku Postgres, Timescale, Crunchy Bridge, and EDB.

<Note>
  The PostgreSQL parser is bundled through `libpg-query`. You do not need a local PostgreSQL server to generate migrations from SQL files or Git refs.
</Note>

## Install

Use npm:

```bash
npm install --save-dev supaschema
```

Other package managers can install the package. This repository uses npm and `package-lock.json`.

## What install adds

Install creates or updates only supaschema-owned setup files:

- `supaschema.config.json`, when missing;
- schema and migrations folders from the detected project layout;
- Claude/Codex-compatible rule, skill, and hook files;
- hook wiring for Claude and Codex-compatible agents;
- a tagged supaschema addendum in `AGENTS.md` and `CLAUDE.md`.

If the installer finds multiple possible schema or migration folders, it records them in `.supaschema/install.json`. Confirm the paths before the first `diff`.

## Verify the binary

```bash
npx supaschema --version
```

## Configure database URLs

Use `supaschema.config.json` for named environments:

```json
{
  "environments": {
    "staging": { "databaseUrl": "$STAGING_DATABASE_URL" }
  }
}
```

Keep real URLs in environment variables. Do not commit credentials.

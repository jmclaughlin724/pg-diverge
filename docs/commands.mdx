## Defaults

When you omit flags, supaschema uses your config.

| Command area | Default |
| --- | --- |
| `--from` | Resolved database URL, then `git:HEAD` |
| `--to` | `dir:<config.schemaPaths[0]>` |
| Migration output | `config.migrationsDir` |
| `check` input | every `.sql` file in `config.migrationsDir` |
| `verify --migration` | newest pending migration |

Global flags work on every command:

<ParamField path="--config" type="path">
  Use an explicit `.json`, `.mjs`, or `.js` config file.
</ParamField>

<ParamField path="--env" type="string">
  Read the database URL from a named `environments` entry in `supaschema.config.json`.
</ParamField>

<ParamField path="--quiet" type="boolean">
  Suppress non-essential output.
</ParamField>

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success |
| `1` | Runtime error |
| `2` | One or more diagnostics contained an error |
| `3` | `--fail-on-diff` found operations |

## Common choices

| Goal | Command |
| --- | --- |
| Generate a migration | `npx supaschema diff` |
| Check generated SQL | `npx supaschema check` |
| Prove apply-twice safety | `npx supaschema verify` |
| Detect drift in CI | `npx supaschema diff --fail-on-diff --quiet` |
| List pending migrations | `npx supaschema migrations` |
| Explain a diagnostic | `npx supaschema explain SUPA_CODE` |

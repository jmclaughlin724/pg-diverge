Use this checklist for an npm release.

The package is designed for trusted publishing from GitHub Actions. `main` is the release source: after the `CI` workflow succeeds on a push to `main`, the release workflow publishes that exact CI-tested commit to npm.

1. Create the public GitHub repository.
2. Add the npm trusted publisher for the repository and `release.yml` workflow.
3. Add a changeset for the release.
4. Run `npm run release:version` and include the resulting package version, lockfile, action metadata, and changelog changes in the release PR.
5. Confirm CI passes all required checks.
6. Merge the release PR to `main`.

Do not publish from GitHub Releases or local machines. The release workflow fails if the committed `package.json` version already exists on npm.

## Required checks

- CI: lint, typecheck, tests, guard suite, package check, benchmarks, fixture diff, fixture verification, corpus oracle, tarball pack, and tarball smoke;
- release preflight: package and lockfile versions match, and the package version is not already on npm;
- release: clean install, signature audit, build, package check, tarball pack, tarball smoke, npm publish, and build-provenance attestation.

## Package boundary

Package contents are allowlisted with `package.json` `files`. Do not add a root `.npmignore`; the package boundary is explicit by design.

Use [Package Boundary](/reference/package-boundary) before adding, moving, or deleting any published file or consumer installer output. Use [Agent bundle](/coding-agents/agent-bundle) before changing shipped agent surfaces or hook behavior.

Before publishing, inspect the dry-run tarball and confirm it contains only the npm package surface:

```bash
npm pack --dry-run --json
```

The release workflow uses:

- `permissions.id-token: write`
- `workflow_run` from the `CI` workflow on `main`
- `actions/setup-node` with `registry-url: https://registry.npmjs.org`
- `npm publish "$SUPASCHEMA_TARBALL" --access public --provenance`

With npm trusted publishing, provenance is generated through GitHub Actions OIDC.

No long-lived npm token is required.

Do not publish from a laptop for production releases.

Use this when a Supabase project should keep `supabase db push` as the runner while `supaschema` generates and proves migrations.

In this setup, Supabase owns apply history. `supaschema` owns schema diffing, replay-safety checks, type output, and optional pre-runner orchestration.

## Use this when

- The repository already has a `supabase/` directory.
- Migrations should stay in `supabase/migrations`.
- Schema files should live in `supabase/schemas`.
- Platform schemas such as `auth`, `storage`, and `realtime` should stay protected.

## Do this

Use the scaffolded Supabase defaults or set the same paths in `supaschema.config.json`:

```json
{
  "schemaPaths": ["supabase/schemas"],
  "migrationsDir": "supabase/migrations"
}
```

Generate, check, and apply:

```bash
npx supaschema diff
npx supaschema check
supabase db push
```

Use `sync` only when you want a guarded wrapper around the Supabase runner:

```bash
npx supaschema sync --local
npx supaschema sync --remote
```

## Verify

Use bare PostgreSQL plus Supabase stubs for disposable verification:

```bash
npx supaschema verify --ensure-environment --ensure-roles
```

Before adopting an existing project, confirm the tree and database agree:

```bash
npx supaschema diff --from database:$DATABASE_URL --fail-on-diff
```

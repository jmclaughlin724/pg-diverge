You can generate a Supabase-compatible PostgreSQL migration without Docker by using `supaschema diff`. `supaschema` reads the declarative SQL files in your repo, compares them to the configured source state, and writes a replay-safe migration file that your normal Supabase runner can apply.

## The problem

Database-backed diff workflows often need a local database, a Docker daemon, or a shadow database to replay the schema before they can compare states. That is slow in large projects and brittle in CI environments where Docker is unavailable or expensive.

`supaschema` avoids that replay step. It parses the schema tree directly with PostgreSQL's parser and renders the migration from the structural difference.

## Install

```bash
npm install supaschema
```

In a standard Supabase project, put declarative SQL files under `supabase/schemas/`.

```bash
mkdir -p supabase/schemas
```

## Generate the migration

Run:

```bash
npx supaschema diff
```

By default, `diff` reads `sources.from` and `sources.to` from `supaschema.config.json`. The scaffolded Supabase config uses `sources.from: "auto"` and `sources.to: "dir:supabase/schemas"`, so it uses the configured database state when available, falls back to `git:HEAD`, and writes a timestamped migration under `supabase/migrations/`.

## Check the migration before applying it

```bash
npx supaschema check
```

`check` verifies that generated SQL is parseable, replay-safe, and free of blocked hazards such as unapproved destructive operations or unsafe `CASCADE`.

When a disposable database is reachable, also run:

```bash
npx supaschema verify
```

`verify` applies the pending migration twice and compares the resulting catalog to the declared schema.

## Apply with Supabase CLI

`supaschema` does not apply migrations to your tracked database. After review and checks pass, keep using:

```bash
supabase db push
```

This keeps ownership clear: `supaschema` generates and proves the migration, while the Supabase CLI applies it.

## CI drift gate

Use `--fail-on-diff` to fail CI when the database and schema tree disagree:

```bash
npx supaschema diff --fail-on-diff --quiet
npx supaschema check
```

See [GitHub Actions CI](/guides/ci-github-actions) for a complete workflow.
